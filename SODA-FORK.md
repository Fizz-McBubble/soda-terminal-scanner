## RC6 Helper 升级边界

R8 临时接管中，旧 2.3.1 Helper 在进程退出后可执行文件消失；现有记录未定位删除者。此前安装器允许一个新数据根关闭另一个数据根的 Helper，且没有先保护旧可执行文件。Helper 2.3.3 拒绝跨根自动接管并提示从旧安装目录同根升级；同根接管在终止旧进程前保存并校验旧文件，替换或启动同步失败时从备份恢复。`*.previous-install` 保留供故障恢复。

当前本地 RC7 r3 候选以已校验 RC6 为源，仅替换 Helper 与 `scanner-runtime.json`；包内 30 个路径与 RC6 一致。有效包位于 `scanner-rc7-local-r3-20260927`，ZIP 为 169,038,143 bytes、SHA-256 `039a8ba7a6d88611bd80b2c05c8917d5fdee35bca00163a47acc166341097fbf`，Helper 为 68,375,274 bytes、SHA-256 `d216d1c21add82e829e0c16a28dbc3132269a14efa929d5905296bb91518a0cd`。隔离 RC6 首次安装、注入失败回滚、成功升级及重复安装在 r3 重跑通过。`source-inputs.json` 记录构建时 HEAD `553c580ee7e41d48d27a6b43b198346c896a90f0`、未提交状态与修改过的源码/打包脚本逐文件哈希；最终冻结仍需关联源码提交。此前 `scanner-rc7-local-20260927` 首次包因过期 R10F capture 标识安装失败；r2 是源码拆分前的旧本地包，均不作为当前候选。

经具名授权的 2026-09-27 Windows 实测使用 r2 字节：切换前原 2.3.1 Helper 文件和协议键正确，进程本来未运行；先备份原 EXE 与目标 HKCU 协议键。隔离 RC7 2.3.3 完成协议注册，`soda-terminal-scanner://` 由 Windows 启动正确 Helper。Edge 153 在授权本地网络后完成配对、带令牌健康读取、撤销与旧令牌 401 拒绝；未发起扫描或账户写入。`finally` 后独立回读：原 EXE SHA-256 `67B2C1D48B0BC2DD86F3D080AEC4E2AC495AAD72D505526E666241822D53F4EE`、原协议命令、无 Helper 进程、43127 无服务，与前态一致。可复验入口为 `Tests/rc7-windows-edge-isolated.ps1`；备份留在隔离候选目录。r3 尚未重复系统协议与 Edge 实测；浏览器可见的外部应用弹窗、运行后异步崩溃回滚或其他用户设备上的升级仍未确认。RC7 尚未公开发布，网页下载指针仍指向 RC6。

## Patch ledger

1. `SCANNER-UPSTREAM-R10B`: treat a strongly blank value ROI in the final substat pair as the terminal boundary when the adjacent name ROI is a visual false positive. This is restricted to the final pair and requires an exact blank value probe; ambiguous or non-terminal incomplete pairs remain fail-closed. Target selection, panel change, complete accepted ROI pairs, stable-frame, duplicate, and partial-result gates are unchanged.
2. `SCANNER-UPSTREAM-R10C`: make Soda's native PP-OCRv6 worker the default OCR engine and keep upstream PP-OCRv5 only as an explicit oracle option. The adapter projects the frozen seven-field contract onto the upstream 450x517 full detail panel, preserves unparseable results as `needs_review`, and writes an R4 staging manifest with dynamic totals and reproducible hashes. Capture/navigation gates from R10B are unchanged.
3. `SCANNER-UPSTREAM-R10D`: normalize PP-OCRv6 stat fields through the drive-disc slot, rarity, level, legal-value ranges, and catalog aliases before the upstream cleaner accepts them. Only a unique domain candidate is accepted; ambiguous values and incomplete substat sets remain named review results. The R10B export is used only by the test replay oracle and is not a production dependency. Model weights, capture/navigation behavior, R4 schema, and the explicit PP-OCRv5 oracle boundary are unchanged.
4. `SCANNER-UPSTREAM-R10E-P1`: make R4 item state depend on complete, uniquely parsed domain fields and known lock state rather than a raw OCR-score diagnostic alone. Low scores remain in field confidence/evidence and telemetry, while parser/field gaps, duplicate or invalid structure, and `lock_unknown` remain fail-closed review blockers. The TypeScript R4 schema, hash resolver, and import semantics are unchanged.
5. `SCANNER-UPSTREAM-R10F`: expose zero-input runtime probes and package the complete self-contained fork as the sole production capture/OCR/R4 executable. The Helper uses the fork session protocol directly and has no automatic legacy capture or PP-OCRv5 fallback. For a Helper-launched elevated child, foreground activation now attaches to the current foreground input thread and verifies that the game handle actually became foreground before any capture or input; failure remains fail-closed as `game_foreground_handoff_failed`. Navigation, panel, OCR-domain, lock, R4 schema, and import semantics are unchanged.
6. `SCANNER-R4-INTEGRITY-R12A`: emit R4 manifest v2 and bind the payload hash to every persisted review-semantic item field: identity, duplicate/lock state, candidate, field evidence, confirmations, issues, state, and capture evidence. `updatedAt` and account-scope storage wrappers are explicitly excluded as bookkeeping. Canonical JSON recursively sorts object keys, preserves array order and nulls, and hashes the UTF-8 bytes with SHA-256; source identity semantics are unchanged.
7. `SCANNER-REVIEW-R11B-P0B`: map only the observed aliases `撩牙重金属` and `療牙重金属` to the existing canonical `獠牙重金属` catalog entry, and project Cleaner diagnostics into one protected R4 v2 root issue plus cascading missing fields. Slot-IV, slot-VI, elemental main-stat, incomplete-substat, and unknown-lock reviews remain fail-closed; capture/navigation, OCR preprocessing, catalog status, and import semantics are unchanged.
8. `SCANNER-REVIEW-R11B-P0C`: preserve the Cleaner export accumulated before a structured parser failure, continue parsing independent substat rows after a main-stat ambiguity, and attach versioned legal-domain options or an explicit `unresolved-only` marker to existing R4 v2 field evidence. Percent/flat stat identity and substat upgrade counts are derived from the same Cleaner value-domain rules, so the existing TypeScript review transaction can reassess user selections without changing the R4 schema. Unresolved fields remain `needs_review`; no default or oracle value is introduced.
9. `SCANNER-USER-JOURNEY-R13D`: publish the player Helper as a background `WinExe`, keep an explicit `--console` diagnostic mode, and let the ordinary-integrity Helper restart only the scanner child through the existing Windows `runas` path when the scanner reports `elevation_required`. A no-output access probe runs before a scan directory is created, so the permission handoff does not create an empty session. Helper and browser both reject duplicate start requests and expose checking, UAC, failure, and retry states; scan, R4, and account-write semantics are unchanged.
10. `SCANNER-OCR-CLOSURE-R18`: consume the frozen `450x517` field geometry directly for every PP-OCRv6 item and materialize each canonical field crop before recognition. This removes the former hand-projected, overlapping row bands and prevents non-zero source offsets from selecting a neighboring heading or row. The same Cleaner and unique-domain acceptance rules remain authoritative; no model, fallback, R4, lock, navigation, or import contract changes.
11. `SCANNER-NAV-OCR-R22`: carry the already-selected native edge target forward as the next visual row 3 / column 1 capture, so a verified one-row advance no longer clicks the previous row's last cell before continuing. The carry is accepted only with changed-list identity, stable selection presence, and stable readable ROIs; insufficient evidence remains fail-closed. PP-OCRv6 parse failures with an empty or low-confidence field receive one same-geometry luminance-normalized pass. Raw and normalized field groups may complement one another, but a result is accepted only when every domain-valid combination converges on one canonical disc; zero or multiple candidates remain `needs_review`. No PP-OCRv5 fallback, guessed value, relaxed domain, account write, or import behavior is introduced.
12. `SCANNER-HELPER-INTEGRITY-R23`: normalize JSON numbers and emit unescaped UTF-8 text when the loopback Helper replaces local evidence paths with opaque browser handles and refreshes the R4 v2 payload hash. This makes the Helper's canonical bytes identical to the browser's `JSON.parse`/`JSON.stringify` contract while preserving the full semantic payload and fail-closed SHA-256 gate. No scan result, evidence image, account data, or formal import is modified.
